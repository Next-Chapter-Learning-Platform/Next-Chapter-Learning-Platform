# Fetch homepage courses from seeded Sanity content

## Goal

Replace the three hardcoded homepage course cards with three server-fetched courses from the private seeded Sanity dataset, preserving the supplied homepage card layout and linking every card to its real `/courses/[slug]` page.

## Source of truth

- UI reference: the user-supplied homepage screenshot and `design/vertex-home.png`.
- Sanity is authoritative for course title, slug, summary, cover image, level, lesson durations, popular status, and module count.
- Preserve the reference's three-column desktop card layout; this task does not turn the homepage into the full catalog.
- The deterministic seeded ordering is `popular desc, title asc`. The current first three are:
  1. Building AI Apps with LLMs
  2. Next.js App Router in Depth
  3. Python for Data Work

## Guidance read

- Repository `AGENTS.md`, especially the approval workflow, private Sanity boundary, grounded-content rule, screenshot reproduction rule, and required checks.
- `sanity-best-practices/SKILL.md` and its Next.js/GROQ references for Server Component fetching, explicit projections, ordering before slicing, image handling, cache tags, and TypeGen.
- Installed Next.js 16.3.3 documentation for server/client boundaries and async Server Component data fetching.

## Existing code and data inspected

- `app/page.tsx`: the homepage is already a Server Component, but its three course cards use an in-file `courses` array and hardcoded Next.js, Docker, and TypeScript marks.
- `app/page.module.css`: the exact three-column card sizing, spacing, typography, metadata row, and responsive two-/one-column behavior.
- `sanity/queries/courses.ts`: existing typed course queries and the correct seeded field names (`popular`, numeric `price`, `duration`, and `freePreview`).
- `sanity/data/courses.ts`: server-only fetch helpers and content cache tags.
- `sanity/lib/fetch.ts`, `client.ts`, `env.ts`, and `image.ts`: private read-token client and server-only image URL builder.
- `sanity.types.ts`: generated result types for the existing course projections.
- `seed.ndjson`: all ten course documents and their referenced lesson durations.
- `next.config.ts`: already allows optimized images only from `cdn.sanity.io/images/**`.
- The live dataset contains 10 courses and 120 lessons. Course cover asset references are currently absent because the remote `picsum.photos` source times out during strict CLI import, so the UI must retain a content-derived fallback until those source assets can be imported.
- The worktree was clean before this prompt was created.

## Decisions and assumptions

- Add a dedicated `HOMEPAGE_COURSES_QUERY` instead of fetching all ten full catalog projections and slicing in React.
- Filter to published course documents with defined slugs, order by `popular desc, title asc`, then slice `[0...3]` before projecting fields.
- Project only `_id`, title, slug, summary, cover image, level, module count, and summed lesson duration.
- Add a server-only `getHomepageCourses()` data helper using existing course and lesson cache tags.
- Keep `app/page.tsx` as an async Server Component and call the helper directly; do not create a client-side Sanity request or loading library.
- Make the whole card a Next.js `Link` to `/courses/[slug]` while preserving article semantics, focus visibility, hover behavior, and the reference's visual structure.
- Use a Sanity image URL when the projected image has an asset reference. Otherwise render a deterministic abbreviation derived from the seeded course title; do not retain the old technology-specific hardcoded marks or invent replacement content.
- Format stored level values for display, format summed seconds as hours/minutes, and pluralize the projected module count.
- If no courses are returned, show a compact non-interactive empty message in the course section rather than rendering stale fallback courses.
- Keep the hero, header, auth controls, search field, weekly message, skyline, and all other homepage behavior unchanged.

## Implementation requirements

### Data query and server boundary

1. Define the homepage GROQ query with `defineQuery`.
2. Filter to courses with a defined slug, order before slicing, and return exactly the fields used by the three card components.
3. Sum referenced lesson durations in GROQ and count embedded modules without fetching modules or lessons into the page.
4. Add a typed server-only data helper with course and lesson cache tags.
5. Fetch the cards only in the async homepage Server Component.
6. Keep the Sanity read token and image URL builder out of client code and the client bundle.

### Homepage cards

1. Delete the hardcoded course array and the Next.js/Docker/TypeScript-specific mark components.
2. Render the three returned documents in the existing desktop/tablet/mobile grid.
3. Show each course's seeded title, summary, formatted level, formatted total duration, and module count.
4. Link the complete card to `/courses/[slug]` with a useful accessible label.
5. Use the seeded Sanity cover when available; otherwise show a title-derived abbreviation in the existing 74px mark treatment.
6. Preserve the screenshot's card dimensions, padding, border, title/body typography, metadata divider, and responsive layout.
7. Add restrained card hover/focus feedback without changing the screenshot's default state.

## Security considerations

- Read the private dataset only through the existing server-only client and helper.
- Never expose `SANITY_API_READ_TOKEN` or import the Sanity client into a Client Component.
- Do not add writes, mutations, browser-side fetching, or raw HTML rendering.
- Sanity slugs are used only to build internal course links; no user-provided external URL is rendered.
- Continue restricting optimized remote images to the configured Sanity CDN hostname and path.

## Acceptance criteria

- The homepage no longer contains a static `courses` array or technology-specific hardcoded course cards.
- The visible three cards match the first three documents from the seeded Sanity ordering.
- Every visible title, summary, level, duration, module count, and slug is sourced or derived from the Sanity query result.
- Clicking any card opens its matching `/courses/[slug]` route.
- The existing desktop screenshot composition and tablet/mobile card reflow remain intact.
- Missing cover references render a stable title-derived fallback without breaking layout.
- No private Sanity credential reaches client code.
- TypeGen, TypeScript, lint, production build, and local browser checks pass.
